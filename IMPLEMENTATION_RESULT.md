## Environment limitations and remaining validation

1. `npm ci` failed with `ENOSPC` (about 179 MiB free). A pre-existing dependency
   tree at `/private/tmp/brainsnn-gpu-current-la2uy4ho/brainsnn-r3f-app/node_modules`
   had a byte-identical lockfile before the Node engine metadata update. A local
   ignored symlink reused it without changing dependencies or deleting unrelated
   files. The actual frontend lint/build and offline tests used that tree. A fresh
   dependency installation still needs disk space.
2. The full existing `npm test`, Python HTTP/runtime suite and private Playwright
   server were attempted. Socket binding failed with `EPERM` / `PermissionError`,
   including `127.0.0.1`. Logs preserve these failures. No permissions or sandbox
   were disabled. `test:offline` explicitly omits the two existing GPU HTTP test
   modules; the default test command and Dockerfile still require every suite.
3. Installing pinned CrewAI in an isolated Python 3.13 environment failed resolving
   `pypi.org`. The real integration test class is explicitly skipped without that
   interpreter/package. Stdlib contract tests exercise actual unavailable-child,
   timeout/cancel/process-reap behavior. CrewAI compatibility and real LLM calls
   must be validated with the installed pinned package, not inferred from tests.
4. Real HTTP worker transport, browser interaction/layout/accessibility, vLLM
   cold-start/warm recovery latency, native CrewAI request serialization, actual
   Comfy generation/decode graph compatibility and human visual review remain
   separate gates. The browser test launcher is isolated from inherited secrets
   and `.env`, and configured to bind loopback on a permitted machine.
5. Website persistence needs a confirmed single replica/process and a durable
   local filesystem volume. This slice does not migrate orchestration into
   Postgres or support independent replicas. Model/render artifacts require
   separately verified durable storage and backup. Container startup, outer
   restart, host Xid recovery and existing monitor ownership remain operational
   prerequisites; the runbook gives the coordinated cutover and rollback order.
6. The actual current Comfy GPU8190/CPU8189 processes, segment06 decoder watcher,
   six existing clips, `/workspace/slava`, models and recovery monitor were not
   accessed or changed. Enabling the new worker before their owners have
   coordinated quiescence is deliberately refused.
7. Socket reads have absolute deadlines and an independent lease timer stops
   owned children even if transport stalls. Python stdlib cannot forcibly cancel
   an OS DNS resolver call; a stuck resolver can still delay the worker's polling
   availability. That availability case requires a real environment check and
   coordinated runtime recovery, not an uptime claim or a competing watchdog.

No rendered fixture, draft, approval record or test result demonstrates a sale,
production reliability percentage, host clearance, or permission to deploy.
