Direct worker API: start with capabilities

The remaining sections document the native worker interface at /v1. Project integrations normally use the authenticated website bridge at /api/world/v1/processing; direct worker integrations require a separately provisioned worker credential. Never distribute a shared legacy operator credential to tenants.

Every direct worker request below except health and signed downloads requires a worker-issued bearer token. Set WORLD_URL to your HTTPS worker and WORLD_TOKEN in your own shell environment. Never embed that token in public frontend code. Downloads through the project bridge also require the project API key in a header.

curl --fail "$WORLD_URL/v1/capabilities" \
  -H "Authorization: Bearer $WORLD_TOKEN"

Only engines returned with available: true can run. The inspect engine returns source integrity receipts without AI. colmap-sparse accepts 3–12 overlapping photographs or one short walkthrough when installed and enabled. It returns camera poses and sparse colored points with unverified scale. When the worker has the pinned MoGe-2 ViT-B depth model (MIT), reconstruction.json also carries scale_estimate: metres per reconstruction unit, estimated by comparing the model's metric depth with the reconstruction's own points on ten frames, with each frame's value and the model's revision and hash. It is an estimate, never a measurement: on three ETH3D scenes with laser-measured ground truth it read 6%, 9% and 16% high, and units stays arbitrary with metric_verified:false. photo-metric accepts one photo and returns photo-metric.ply, a 3D point preview of what the photo shows in estimated metres, and photo-metric.json with the model's revision and hash, the estimated field of view and the depth range. The same MoGe-2 model as scale_estimate predicts it; the camera is solved from the photo alone. Over 18 ETH3D photos with laser-measured truth its depth was off by a median 7.9% (worst 27%). It is not measured, not generative (nothing is invented behind what the camera saw) and never a collision map; the manifest keeps units: arbitrary. colmap-dense-cpu is the same reconstruction with dense points as well: a depth model per frame (Depth Anything V2 Small, Apache-2.0), aligned to that frame's triangulated points and kept only where neighbouring frames agree. They are less accurate than the sparse points, and nothing about them is metric until you measure a distance. scene-usd accepts one walkthrough video and adds a simulation scene compiled in Blender to those reconstruction artifacts: scene.glb and scene.json, with the observed floor and walls, unseen floor as tagged unknown volumes and nothing inferred. From a video its units are arbitrary and it writes no scene.usda. It also accepts one cloud upload instead: the Arena point-cloud JSON that World Builder exports (.json, up to 16 MiB, 50,000 points and a 250 × 250 m footprint). A cloud scaled by a distance the user measured compiles to a metric scene with scene.usda (metersPerUnit = 1) and scene.ifc (IFC4, metres) for BIM tools, with each element's provenance in Pset_BrainSNN, plus scene-plan.dxf (a plan in metres for CAD), scene.3dm (a Rhino model of named, measured boxes) and quantities.csv (floor extent, wall lengths and areas, every object) when the worker has the CAD libraries. It also writes fit-check.json and fit-heatmap.ply: every point's distance to the nearest model surface, per kind and per element, with misfits flagged. That is model to points, not a survey tolerance. Every cluster of points above the floor that is not a wall becomes its own object with an oriented box in metres, in scene.json and as its own element in GLB, USD and IFC. That scale stays self-reported and unverified, and single-photo previews are refused.

mapanything-apache provides dense point previews on a separately qualified GPU. world-observations accepts one photo or MP4/MOV video and proposes up to six selected labels from at most four frames using the operator’s local vision model. Video decoding supports software H.264, HEVC, MPEG-4 and AV1 in MP4/MOV. HEVC has been tested with synthetic SDR clips; HDR and physical-phone captures remain unqualified. WebM needs compatible conversion first. Its outputs include exact source/frame hashes, decoded video timestamps, derivative images and model provenance. Suggestions are partial and omit localization boxes. Review each against its frame before keeping it.

The browser's on-device photo preview runs separately. Its model download requires consent and sends no source photo to this API.

Provision separate private owners

Set WORLD_TENANTS_FILE to an absolute private JSON file. Each tenant has a stable operator-chosen ID and the SHA-256 of a randomly generated URL-safe credential (at least 32 random bytes). Distribute only that tenant’s credential through your private channel. The registry must never contain plaintext credentials. This is private provisioned access, not public account registration or payment authorization.

{
  "schema": "brainsnn.world.tenants.v1",
  "tenants": [{
    "id": "studio-a",
    "token_sha256": "<64 lowercase hexadecimal characters>",
    "enabled": true,
    "engines": ["inspect"],
    "limits": {
      "upload_count": 12,
      "upload_bytes": 536870912,
      "job_count": 12,
      "active_jobs": 1,
      "storage_bytes": 6442450944
    }
  }]
}

The example limits are the defaults on the standard 20 GiB worker. Limits must be positive integers within the worker’s global caps. inspect is the default engine grant; additional configured engines need an explicit allowlist entry. Capabilities show only that credential’s permitted engines and return owner_id, access_mode and owner_limits. operator_only:true and public_processing:false remain in effect.

Every upload, job and artifact belongs to its authenticated owner. Owner IDs sent by a browser cannot assign ownership. Cross-owner reads, resume writes, input references, cancellation, deletion and ticket creation return 404. Existing records migrate only to the reserved operator owner; scoped credentials cannot adopt them. The legacy operator API credential is also limited to its own records. All owners still share the stricter global disk cap, one execution slot and eight queue slots.

Prepared, queued and running jobs reserve capacity. A cancelled process retains its reservation until it stops. Retained uploads/jobs count against owner allowances until deletion or expiry. Lowered limits apply at admission and before queued execution; already-running jobs keep their accepted bounded execution. This slice does not provide metered compute credits or paid execution authorization.

Replace the registry atomically. Invalid configuration prevents startup; a missing or invalid registry during operation denies tenant access without granting operator privileges. Removing/disabling a tenant revokes new requests and existing download tickets. Rotating its credential hash preserves the same owner’s data while revoking the old credential and tickets. Never reuse an owner ID for a different customer. Queued work checks current owner/engine authorization before starting; already-running work is not cancelled by registry edits.

Download tickets bind one owner, credential generation, job and artifact for at most 60 seconds. They use a separate server-only signing key and expire on worker restart. Anyone possessing a valid ticket can download that artifact until expiry or revocation; keep the URL private. Database ownership checks do not isolate adapter processes: adapters still share a service account and filesystem. Public hosting additionally requires qualified process isolation, durable storage/queueing and compute/billing budgets.

Use the result without losing its meaning

Artifacts carry their byte size, SHA-256 and metric_verified:false. Verify the bytes before use. Point clouds and Gaussian splats represent appearance; neither is a collision map. Model-estimated dimensions remain unverified until checked independently.

Import a RoomPlan or BrainSNN map into World Builder, check scale and obstacles, then export the reviewed geometry to Arena or export the route and assumptions as an evidence pack. The browser's content hash detects changes; it does not authenticate an author or certify robot safety.

World Builder uses the original floor polygon when planning imported scans. Unknown regions are blocked. Estimates cover a conservative planar route and your supplied time/cost assumptions; they do not execute a learned robot policy.

Turn a reconstruction into a robot planning map

A colmap-sparse job returns sparse-preview.ply and reconstruction.json with camera poses. The repository's Node tool runs the same proposal as World Builder's Real → sim card. It finds up from how the phone was held and the floor from the lowest dense layer of points. Obstacles are dense points up to robot height, free space is where the camera walked or floor was seen, and unseen areas stay blocked.

cd brainsnn-r3f-app
npm run world:propose -- --points sparse-preview.ply --evidence reconstruction.json \
  --out world.json --report proposal.json \
  --measure "ax,ay,az;bx,by,bz;0.90"   # or --camera-height 1.35

Scale comes from a distance you measured in the room. Give its two ends in the reconstruction's own coordinates; World Builder's "Pick two measured points" records them in the proof pack. Without a measurement, scale comes from the worker's scale_estimate when the reconstruction has one (labelled estimated in the map's warnings and scaleSource: estimated-metric-depth), else from an assumed phone height (default 1.35 m; --camera-height forces it). A measured pair that implies a phone height outside 0.3–2.5 m is refused; an estimate that does is kept with a warning to measure. proposal.json records each input's SHA-256, so compare them with the job's artifact hashes.

world.json is brainsnn.world.v1 with provenance: observed and both review flags false. Import it into World Builder, check scale and obstacles, then plan or export to Arena or OpenUSD. The tool never marks a map reviewed, and exports stay blocked until a person does.

Component fit and targeted recapture

Metric scenes with bound component evidence also return component-fit.json. It records per-component reconstruction residuals, limited wall-refinement candidates and recapture requests. A fit measures agreement with the reconstructed cloud; it does not verify physical dimensions. Unsupported openings, unseen floor and hidden wall thickness stay unchecked. Corrections require explicit component selection through the offline refinement tool, rebuild the exports and invalidate earlier review state. See docs/world-component-fit.md for the review and rebuild commands.

Check dimensions against independent readings

Metric scene-usd jobs return scene-measurements.json: unchecked box dimensions and optional comparisons with operator-reported tape, laser or dimensioned-reference readings. A cloud may include a bounded measurementChecks contract bound to its exact ordered points. Calibration readings are excluded from the held-out result. Changed points invalidate the binding; the report never rescales geometry or marks it verified.

The browser provides 3D landmark picks, reading provenance and per-check results when the engine declares dimension_checks:true. It verifies the returned report against the ordered cloud and exact scene artifact hashes. Changing the capture or scale clears stale review state. Run python -m robotics.world_worker.measurement_check --help for offline checks. The input schema is in docs/world-dimension-checks.md in the repository. Passing point-pair comparisons do not independently validate every BIM element; metric_verified remains false.

Review hosted BIM openings

A qualified scene-usd engine declaring bim_review:true accepts a bounded bimReview object in a metric cloud. Each explicitly reviewed rectangular opening names an existing wall, includes its exact geometry snapshot and binds to the ordered cloud hash. The worker rejects stale hosts, changed points, overlapping openings and out-of-bounds dimensions. IFC uses hosted void and optional door-filling relationships, with matching cuts in visual and CAD exports. A door is a closed reference leaf; swing, clearance and physical accuracy remain unvalidated.

Send the previous same-owner scene job as source_job when recompiling unchanged points and scale. This preserves the exact prior object-name suggestions with a reuse receipt and avoids a new model call. It does not approve those suggestions. See docs/world-bim-review.md for placement and contract details. Changed source, scale or host geometry requires another review.

Draft a tabletop robot task

The World Builder website preview accepts POST /api/world/robot-task-draft with an owner session bearer token from /api/world/session. The site operator supplies GEMINI_API_KEY. Each approved draft uses one call from the site’s Gemini allowance.

{"consent":true,"brief":"Push the puck 30 cm"}

Send JSON with up to 1,200 characters of text. A chosen image or short video of up to 2 MiB can accompany the request in reference, with mimeType and standard base64 data. A reference alone can use an empty brief. Google receives the chosen file in full.

A supported draft returns {"task":"push","distanceCm":30} or a reach task. An idea outside the tabletop tools returns {"task":"unsupported"}. Review the draft and run it locally in MuJoCo. Open the robot task builder.

Private data by default

Selecting a file in the app creates a local reference. A remote job needs explicit upload consent naming the worker. Browser access tokens stay in page memory. Sources are not used to train models by this pipeline. The observation adapter sends bounded frame derivatives to a loopback vision model on the worker host; it has no hosted-provider fallback. Signed download URLs grant temporary access to one artifact; keep them private.

Deploy workers behind TLS with persistent storage and quotas. Public hosted access additionally needs qualified process isolation, durable storage and queueing, per-user compute budgets and billing authorization; this private API is not that service.
