Use the same authenticated processing API behind World Builder from a robotics app, a command-line tool or your own interface.

Operator beta: bring a privately configured worker. Public signup and hosted reconstruction are not available yet. Legacy mode uses one private operator credential. Operators may additionally provision owner-scoped credentials; never distribute the legacy operator credential to tenants.

Start with worker capabilities

Every request below except health and signed downloads requires an operator-issued bearer token. Set WORLD_URL to your HTTPS worker and WORLD_TOKEN in your own shell environment. Never embed that token in public frontend code.

curl --fail "$WORLD_URL/v1/capabilities" \
  -H "Authorization: Bearer $WORLD_TOKEN"

Only engines returned with available: true can run. The inspect engine returns source integrity receipts without AI. colmap-sparse accepts 3–12 overlapping photographs or one short walkthrough when installed and enabled. It returns camera poses and sparse colored points with unverified scale.

mapanything-apache provides dense point previews on a separately qualified GPU. world-observations accepts one photo or MP4/MOV video and proposes up to six selected labels from at most four frames using the operator’s local vision model. Video decoding supports software H.264, HEVC, MPEG-4 and AV1 in MP4/MOV. HEVC has been tested with synthetic SDR clips; HDR and physical-phone captures remain unqualified. WebM needs compatible conversion first. Its outputs include exact source/frame hashes, decoded video timestamps, derivative images and model provenance. Suggestions are partial and omit localization boxes. Review each against its frame before keeping it.

The browser's on-device photo preview runs separately. Its model download requires consent and sends no source photo to this API.

Limit: 200 MiB per source, up to 12 source files per job (query the selected engine’s smaller limit), one running job, eight queued jobs. Uploads and outputs expire after the worker's retention window (24 hours by default). Query capabilities for the current limits. A video reconstruction still needs overlap, parallax and usable detail; insufficient evidence returns a failure.

Provision separate private owners

Set WORLD_TENANTS_FILE to an absolute private JSON file. Each tenant has a stable operator-chosen ID and the SHA-256 of a randomly generated URL-safe credential (at least 32 random bytes). Distribute only that tenant’s credential through your private channel. The registry must never contain plaintext credentials. This is private provisioned access, not public account registration or payment authorization.

{
  "schema": "brainsnn.world.tenants.v1",
  "tenants": [{
    "id": "studio-a",
    "token_sha256": "<64 lowercase hexadecimal characters>",
    "enabled": true,
    "engines": ["inspect"],
    "limits": {
      "upload_count": 12,
      "upload_bytes": 536870912,
      "job_count": 12,
      "active_jobs": 1,
      "storage_bytes": 6442450944
    }
  }]
}

The example limits are the defaults on the standard 20 GiB worker. Limits must be positive integers within the worker’s global caps. inspect is the default engine grant; additional configured engines need an explicit allowlist entry. Capabilities show only that credential’s permitted engines and return owner_id, access_mode and owner_limits. operator_only:true and public_processing:false remain in effect.

Every upload, job and artifact belongs to its authenticated owner. Owner IDs sent by a browser cannot assign ownership. Cross-owner reads, resume writes, input references, cancellation, deletion and ticket creation return 404. Existing records migrate only to the reserved operator owner; scoped credentials cannot adopt them. The legacy operator API credential is also limited to its own records. All owners still share the stricter global disk cap, one execution slot and eight queue slots.

Prepared, queued and running jobs reserve capacity. A cancelled process retains its reservation until it stops. Retained uploads/jobs count against owner allowances until deletion or expiry. Lowered limits apply at admission and before queued execution; already-running jobs keep their accepted bounded execution. This slice does not provide metered compute credits or paid execution authorization.

Replace the registry atomically. Invalid configuration prevents startup; a missing or invalid registry during operation denies tenant access without granting operator privileges. Removing/disabling a tenant revokes new requests and existing download tickets. Rotating its credential hash preserves the same owner’s data while revoking the old credential and tickets. Never reuse an owner ID for a different customer. Queued work checks current owner/engine authorization before starting; already-running work is not cancelled by registry edits.

Download tickets bind one owner, credential generation, job and artifact for at most 60 seconds. They use a separate server-only signing key and expire on worker restart. Anyone possessing a valid ticket can download that artifact until expiry or revocation; keep the URL private. Database ownership checks do not isolate adapter processes: adapters still share a service account and filesystem. Public hosting additionally requires qualified process isolation, durable storage/queueing and compute/billing budgets.

Optional: sign completed-job receipts

Reporting stays disabled until a persistent private key is explicitly configured; no credential or download-ticket key is ever reused. Generate the key pair once, outside the worker's storage tree:

python -m robotics.world_worker.report_receipts init-key \
  --private-key /operator/report-signing.key \
  --public-key  /operator/report-signing.pub

The private key must be an absolute path to a regular 32-byte file with mode 0600, and it must live outside the WORLD_WORKER_DIR tree — otherwise startup fails. Signing requires the dependencies in requirements-report-receipts.txt. Set WORLD_REPORT_SIGNING_KEY to the private key path to enable it; the public key is served at GET /v1/report-key (schema brainsnn.world.report-key.v1: algorithm, keyId = SHA-256 of the raw key, publicKey in canonical base64url) and advertised in /v1/capabilities under reportSigning.

After a job completes, request a receipt by name with the SHA-256 of each artifact you want covered:

curl --fail -X POST "$WORLD_URL/v1/jobs/$JOB/report-receipt" \
  -H "Authorization: Bearer ***" -H "Content-Type: application/json" \
  -d '{"scenarioSha256":"<64 hex>","geometrySha256":null,"artifactRefs":[{"name":"<artifact>","sha256":"<64 hex>"}]}'

Scenario and geometry digests are owner-declared linkage; the receipt never asserts measurements, safety, policy execution or independent host attestation — every such flag is fixed to false.

The worker re-reads the selected artifact bytes and verifies each against its recorded SHA-256 before signing, refusing links and any observed mutation. The verification thread holds the single hash slot until it stops, so a disconnected request cannot free the slot early. One verification at a time: a concurrent request returns 429; if re-hashing the evidence exceeds the worker's time budget the request returns 504 and the slot is released when the thread finishes. The signed envelope is at most 64 KiB; selected artifact bytes are capped at 256 MiB per receipt (413 above). The request carries only digests and artifact names — never the source or artifact bytes. After IO completes, the worker re-authenticates the caller and re-checks the job evidence; a revoked identity or changed evidence yields 401/409 with no new signature.

Verify offline against a key you trust independently — an embedded public key never establishes trust:

python -m robotics.world_worker.report_receipts verify \
  --receipt receipt.json \
  --trusted-public-key /operator/report-signing.pub \
  --scenario scenario.json

The verifier re-checks the signature, the payload against its exact schema, and the exact local scenario file bytes against the signed owner declaration. The claim states what was verified; measurements, model truth and host independence remain unverified.

Use the result without losing its meaning

Artifacts carry their byte size, SHA-256 and metric_verified:false. Verify the bytes before use. Point clouds and Gaussian splats represent appearance; neither is a collision map. Model-estimated dimensions remain unverified until checked independently.

Import a RoomPlan or BrainSNN map into World Builder, check scale and obstacles, then export the reviewed geometry to Arena or export the route and assumptions as an evidence pack. The browser's content hash detects changes; it does not authenticate an author or certify robot safety.

World Builder uses the original floor polygon when planning imported scans. Unknown regions are blocked. Estimates cover a conservative planar route and your supplied time/cost assumptions; they do not execute a learned robot policy.

Private data by default

Selecting a file in the app creates a local reference. A remote job needs explicit upload consent naming the worker. Browser access tokens stay in page memory. Sources are not used to train models by this pipeline. The observation adapter sends bounded frame derivatives to a loopback vision model on the worker host; it has no hosted-provider fallback. Signed download URLs grant temporary access to one artifact; keep them private.

Deploy workers behind TLS with persistent storage and quotas. Public hosted access additionally needs qualified process isolation, durable storage and queueing, per-user compute budgets and billing authorization; this private API is not that service.
