# World Builder camera setup review

The owner shared [Florian Delaplace’s HumanCalib post](https://www.linkedin.com/posts/florian-delaplace-phd_biomechanics-markerlessmotioncapture-computervision-ugcPost-7528802939746930689-LXuy/). HumanCalib estimates extrinsics from a walk captured by synchronized, fixed cameras with known lens intrinsics and subject stature. The authors report median relative orientation error of 0.84° across 97 trials. Their held-out or reference comparisons belong to the upstream study. The local run qualifies software execution on the fitting data. [Preprint](https://hal.science/hal-05855397v1) · [Pinned HumanCalib v0.5.4](https://github.com/flodelaplace/HumanCalib/releases/tag/v0.5.4)

Built a local prototype inside **Change things → Make it yours → Understand movement → Check a camera setup**. It imports a finished Pose2Sim/HumanCalib TOML and an optional OpenSim TRC entirely in the browser. It supports camera centres/directions, two projection planes, timestamped marker scrubbing, bounds checks, file fingerprints, clearing and an original authored example. Each source view preserves its own frame and exposes no inferred fit score. This prototype opens prior calibration results. Generating a fresh calibration from recordings is separate. Prototype code is `b870cdc447316f4182a82ce21a421adb3b4e6d1e` on `codex/world-camera-calibration-20261118`; isolated worktree `/Users/slavaz/the-brain-camera-calibration-20261118`. Production deployment was outside this exploratory increment.

Upstream v0.5.4 (`97672f772e316a2649a7805f31a282f35cf0bc4b`) ran its 193-pass/1-skip suite plus a fresh CPU calibration, bundle adjustment, scale and triangulation on 20 cached frames from four cameras. The fit residual fell from 5.121 to 3.407 pixels and yielded genuine TOML and 87-marker TRC. Blank clips supplied metadata only. There was no video inference and no independent physical accuracy measurement. Chromium and WebKit imported both outputs, matched SHA-256 fingerprints, drew both views, checked clearing and invalid input, and fit the panel at 320/390 px with large text. No network mutations or page errors occurred. Existing actual OpenSim workflows passed in both browsers, all 498 World tests passed, and lint/build passed.

The exact HumanCalib paired export conversion is Z-up TOML → Y-up TRC `(x,y,z) → (y,z,x)`. TOML uses OpenCV world-to-camera extrinsics (`C=-R^Tt`). The TOML exporter preserves the incoming metadata `error` value and must not be used as a fit score. A locally low reprojection residual can coexist with incorrect absolute scale/position. TRC carries points, so model-specific IK/scaling is needed for `.mot/.sto`, and a separate fit is needed for SOMA BVH. Scene alignment needs surveyed references or checked correspondences independent of the walk.

The numerical solver is MIT. Its default MeTRAbs weights and the alternate VideoPose3D stack have noncommercial restrictions. A commercial video-to-calibration feature needs a qualified pose pipeline whose exact model terms permit the use. Existing MoveNet is a 2D starting point, not a drop-in camera-frame 3D lift. Prefer an authorized multi-camera benchmark with independent checkerboard or surveyed references before enabling an API job.
