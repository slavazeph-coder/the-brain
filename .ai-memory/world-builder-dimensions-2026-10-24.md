## Competitive and integration research, 25 October 2026

The owner supplied IMG_0898.jpeg and asked how to improve beyond Matterport/Polycam while supporting robotics and BIM/Rhino. Its montage labels a Blender-rendered synthetic room, 20,792 points, 60 poses, seven held-out checks and a shown largest difference of 1.9 cm. Treat those as reported synthetic pipeline evidence, not real phone accuracy.

Current official sources show existing overlap: Matterport already offers LOD 200 BIM and Revit integration (https://matterport.com/bim); Polycam Reconstruction API explicitly supports photo inputs, robotics and simulation (https://poly.cam/reconstruction-api); Metaroom offers IFC/DXF/USD from LiDAR-enabled Apple devices (https://help.amrax.ai/sample-page/export-integrations/what-export-formats-does-metaroom-studio-support/); NavVis IVION already has navigation graphs/routing (https://knowledge.navvis.com/docs/routing). No broad superiority claim is established.

Recommended next engineering slice: capture-scoped stable element IDs and an editable architectural graph, shared IFC/Rhino/robot exports, then a Nav2 map package and closed-loop tests against independent reference geometry. Current IFC GUIDs are name-seeded; Rhino object IDs are newly assigned during export. Worker scene.usda is visual geometry with units/upAxis, without physics collision authoring. rhino3dm supports independent geometry/file operations (https://github.com/mcneel/rhino3dm); Rhino.Compute introduces Windows/licensing dependencies, so defer until needed (https://developer.rhino3d.com/guides/compute/deploy-to-iis/). Isaac USD prims have no physics by default (https://docs.isaacsim.omniverse.nvidia.com/latest/physics/simulation_fundamentals.html).

CRAB, submitted 21 October, is a relevant component/topology representation reference (https://arxiv.org/abs/2610.29257). Author thickness MAE 2.80 cm is on Structured3D, not camera survey validation; downloadable code/weights were not verified from its sparse project page. For reproducible ablations prefer the separate MapAnything Apache weights and SAM 2 masks, retaining current COLMAP/calibration. DA3-BASE is an optional small relative-geometry comparison. SpatialLM encoder weights remain noncommercial. Do not combine author hardware/memory numbers or scale-aligned camera trajectory metrics into physical BIM accuracy claims. No new inference or market comparison was executed in this research pass.

The next physical acceptance study should retain one calibration and independently withheld spans, test native IFC/Rhino edit/save/reopen with stable IDs, and score robot completion/collisions/false-free cells against a separate reference world. Cross-format millimetre agreement is serialization consistency; simulation success is separate from physical robot validation. Estimate implementation effort/cost explicitly and qualify 4090/GB10 availability and package support rather than assuming either is reachable.
