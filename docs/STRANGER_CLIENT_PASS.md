# GaugeGap / BrainSNN Stranger and Client Pass

## Executive finding

The product demonstrates unusual technical breadth, but the previous public journey optimized for **showing everything built** rather than helping a stranger decide:

1. what this is,
2. where to start,
3. why it matters to them,
4. what BrainSNN has to do with GaugeGap,
5. what an organization can buy,
6. and how to begin a conversation.

The next growth constraint is no longer the number of experiments. It is **clarity, conversion and proof of use**.

## End-to-end stranger journey

### 1. Search result and domain

Observed public titles were inconsistent across the apex and `www` hosts, and neither reflected the latest GaugeGap title during the pass. This makes the product appear stale before the page is used.

**Required outcome:** one canonical host, one current title, one deployed build.

### 2. Hero

The previous hero was strong entertainment copy but did not explain the product relationship.

**New framing:**

- GaugeGap = the playable science and interaction surface.
- BrainSNN = the analysis, decision and publishing engine underneath.
- Client value = turn a hard idea into something an audience can operate.

### 3. First decision

Twelve equal-weight experiments create choice overload. A first-time visitor should not need to compare twelve cards before seeing value.

**New path:** four intent-based starting routes plus four recommended experiments. The full twelve remain accessible through topic filters.

### 4. First experiment

The experiment must load quickly and make its mission obvious. Loading all twelve simulation engines on the first page penalizes every visitor for code they may never use.

**New behavior:** experiment components load on demand, while direct links still open the requested lab.

### 5. Trust

A visual model can be mistaken for a validated result. The site needs an explicit ladder:

- **Play** — explore behavior and build intuition.
- **Teach** — connect controls to the mechanism.
- **Verify** — expose parameters, assumptions, diagnostics and limitations.

The current public arcade should be described as educational numerical models. Stronger scientific claims belong only in releases that expose the evidence boundary.

### 6. Client conversion

The previous page had no public answer to “Can you build this for us?”

**New client pathways:**

- schools, museums and training,
- publishers and creators,
- brands and campaigns,
- research and innovation teams.

Each pathway now explains likely outputs and opens a prefilled pilot brief to `hello@brainsnn.com`.

### 7. Page length and repetition

The page previously displayed the twelve experiments in the arcade and then repeated the full catalogue again below it.

**New structure:** the duplicate catalogue is removed. The lower section now highlights only the three deeper tools: research, content analysis and claim reconstruction.

## Funnel to measure

The analytics allowlist previously dropped the new GaugeGap events silently. The public funnel now has named events, but a real analytics sink still needs to be connected.

Recommended funnel:

1. `gaugegap_landing_viewed`
2. `gaugegap_pathway_selected`
3. `gaugegap_lab_selected`
4. share or completed-mission event
5. `gaugegap_client_cta_clicked`
6. qualified pilot conversation

Key rates:

- landing → pathway selection,
- pathway → experiment interaction,
- experiment → share,
- landing → client CTA,
- client CTA → replied email,
- pilot brief → paid prototype.

## Remaining priority backlog

### P0 — before promotion

- Confirm `brainsnn.com` and `www.brainsnn.com` resolve to the same current deployment.
- Confirm the deployed title is `GaugeGap Foundry | Play with the impossible`.
- Verify every lab on iPhone Safari and desktop Chrome.
- Connect analytics events to a real privacy-conscious analytics destination.
- Confirm `hello@brainsnn.com` receives mail.

### P1 — client readiness

- Publish one real case study or internal pilot with before/after engagement evidence.
- Create one downloadable pilot brief or one-page capabilities sheet.
- Add a calendar booking route after the email pathway proves demand.
- Add a lightweight statement of data handling for BrainSNN content scans.
- Define a repeatable pilot scope, timeline and commercial range.

### P2 — growth

- Give each experiment a crawlable route and dedicated social preview image.
- Add mission-completion events rather than awarding value only for opening a lab.
- Add public challenge collections and curated weekly themes.
- Generate video/post assets from the exact run state.
- Add classroom and campaign templates only after usage data identifies the strongest labs.

## Product discipline

Do not add another twelve experiments yet.

First prove that strangers can:

- understand the product,
- start a lab,
- finish a mission,
- share a state,
- and request a pilot.

The next durable moat is not library size. It is the combination of a reusable interaction engine, measurable audience behavior, reproducible states and a repeatable client delivery process.
