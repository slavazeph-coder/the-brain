# Review a camera setup in World Builder

Open **Change things → Make it yours → Understand movement → Check a camera setup**. Start with **Try an example**, or select a finished HumanCalib or Pose2Sim camera `.toml` and optionally the calibration walk `.trc`. Choose **Open setup**. The camera view shows positions, pointing directions and image sizes. Choose **Walk points** to review the marker samples frame by frame. The browser reads the files locally and shows their SHA-256 fingerprints under **Camera positions and source files**. The files are held for the current page and can be removed with **Clear setup**.

The review accepts 2–16 standard OpenCV pinhole cameras in a `.toml` file up to 128 KiB. Camera translations follow the Pose2Sim metre convention. The walk accepts an OpenSim-format `.trc` file up to 8 MiB with metre, centimetre or millimetre coordinates, and displays the samples in metres on the original file axes. The limit is 6,000 frames, 128 markers, and 500,000 frame-marker pairs. Entirely missing samples appear as gaps. Camera and marker views preserve their own file coordinates. The viewer checks file structure and exposes visually inspectable geometry. Independent physical references are needed to measure accuracy and register a rig to a room.

HumanCalib estimates camera placement from synchronized videos from fixed cameras with overlapping views. It uses previously known lens intrinsics and measured stature for metric scaling. In v0.5.4 its two exports share a heel-based origin but use different axes. To express a point from the Pose2Sim Z-up camera file in its paired OpenSim Y-up TRC frame, transform `(x, y, z)` to `(y, z, x)`. The calibration file copies some source metadata, so its `error` field is insufficient to establish reprojection fit. [HumanCalib usage](https://github.com/flodelaplace/HumanCalib/blob/v0.5.4/HOWTO.md) · [Pinned coordinate conventions](https://github.com/flodelaplace/HumanCalib/blob/97672f772e316a2649a7805f31a282f35cf0bc4b/src/humancalib/core/frames.py)

World Builder currently opens existing calibrations. A future capture workflow would take synchronized recordings and run a qualified detector and calibration solver, then verify the result against held-out measurements. The bounded solver can run on CPU with imported detections. The MIT calibration code and the pretrained video models have different terms. Both upstream inference routes include noncommercial model weights. [HumanCalib license table](https://github.com/flodelaplace/HumanCalib/blob/v0.5.4/README.md#licensing)

The calibration walk contains marker trajectories. For OpenSim analysis it first needs model fitting and inverse kinematics to produce matching `.mot` or `.sto` joint coordinates. For SOMA retargeting it needs a separate fit to the supported BVH skeleton and rotations. [OpenSim input contract](world-biomechanics.md) · [SOMA input contract](world-motion-retarget.md)
